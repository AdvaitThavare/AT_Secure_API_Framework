# AT Secure API Framework

A TypeScript-based API security testing framework built with Playwright for local HTTPS/mTLS testing and application-level encryption flows.

## Current Scope

* TypeScript and Node.js
* Playwright API testing
* Local HTTPS server
* Mutual TLS (2-way SSL)
* JSON and plaintext payload testing
* Request validation and normalization
* Encryption strategy routing
* JWE
* AES_RSA
* JWS_AES_RSA
* Standardized application error handling
* Postman interoperability testing

## Architecture

The current request/response flow is:

```text
Client / Postman
      |
      | HTTPS + mTLS
      v
HTTP Server
      |
      v
Request Identification
      |
      v
Validation / Normalization
      |
      v
Cryptography
      |
      v
Service
      |
      v
Cryptography
      |
      v
HTTP Response
```

Cryptography is routed through a common strategy layer:

```text
Encryption Type
      |
      v
Crypto Strategy
   |       |
   v       v
decrypt() encrypt()
```

See `Architecture.md` for the detailed architecture and task roadmap.

## Encryption Methods

### JWE

Uses authenticated encryption with:

```text
RSA-OAEP-256
      +
AES-256-GCM
```

### AES_RSA

Encrypts the plaintext using AES and encrypts the AES key using RSA:

```text
Plaintext
    |
AES-256-CBC
    |
Encrypted Payload

AES Key
    |
RSA/PKCS#1 v1.5
    |
Encrypted Key
```

Configuration:

* AES-256-CBC
* PKCS#7 padding
* 16-byte IV
* RSA/PKCS#1 v1.5
* No signature

The absence of a signature is intentional for this protocol.

### JWS_AES_RSA

Signs the plaintext before encrypting it:

```text
Plaintext
    |
RS256 JWS
    |
Signed Plaintext
    |
AES-256-CBC
    |
Encrypted Payload

AES Key
    |
RSA/PKCS#1 v1.5
    |
Encrypted Key
```

Configuration:

* RS256
* AES-256-CBC
* PKCS#7 padding
* 16-byte IV
* RSA/PKCS#1 v1.5

## Request and Response Format

AES_RSA and JWS_AES_RSA use an encrypted wrapper.

The request is normalized before reaching the individual cryptography strategy:

```json
{
  "encReqPayload": "...",
  "encReqKey": "..."
}
```

The response is generated by the corresponding cryptography strategy:

```json
{
  "encResPayload": "...",
  "encResKey": "..."
}
```

The normalization layer isolates external wrapper naming from the internal cryptography strategy interface.

## Testing

### Setup

Install dependencies:

```bash
npm install
```

Compile the project:

```bash
npx tsc
```

### Postman

Postman is currently used for interoperability and positive-flow verification.

The following flows have been verified:

* JWE
* AES_RSA
* JWS_AES_RSA

Automated regression testing can be expanded as the architecture evolves.
